# Private fruit-stage review

Tools → Analisis Orthomosaic → Agro_ABC → A/B/C now includes **Dugaan mulai berbuah**. Enable its markers, choose a gawangan or point, inspect the original TIFF, and choose **Mulai berbuah menurut tim**, **Bukan indikasi buah**, **Belum jelas**, or **Belum diperiksa**. Save notes with a decision or **Simpan catatan buah**. Staff may add a missing fruit-review point on ready native pixels. These are independent annotations: confirming fruit never accepts a pineapple census candidate or changes plant counts. Rejecting fruit never deletes a pineapple. Export includes the saved decisions and per-zone status table.

This is a review shortlist, not a validated fruit detector. The owner example `A-radial-x14277-y24744` was matched to original pixels in GT-A-03 at longitude 102.00602332386882, latitude 0.5825934480801848. Owner interpretation is retained as provenance, not an automatic confirmed label. Native compact pale centres are ranked by 13-pixel grayscale template similarity at four rotations, threshold 0.65, with 55-pixel spacing. Up to five per revised gawangan are selected, plus the owner example. Source active/dead categories do not determine whether plants are dead or bearing. Similarity is not confidence or probability. Leaves, glare and debris remain false positives; stage precision/recall are unknown. Neither zero nor five proposals estimates abundance. Existing detector misses and manual plant additions are not automatically screened by this first pass.

Run `scripts/dayun_fruiting_shortlist.py --native-root <existing-original-tiles> --analysis-root <current-private-results> --out <private-output>` using the existing raster runtime. Original tiles are never resampled for detection; previews enlarge pixels only. The output JSON records source run, geometry revision, method, reference hash, limitations and source-pixel IDs. GeoTIFF date is not treated as verified flight date. Same-ID polygon parts are counted once by zone ID; overlaps remain multi-membership and must not be summed as unique plants across zones.

Private manifest `block_fruiting` maps A–C to immutable allowlisted proposal files. `GET/POST /api/staff/drone/analysis/Agro_ABC/fruiting-review?block=A` uses existing staff authentication and the DroneQueue coordinator. The server binds run, block and proposal path, derives zone membership against current revised polygons, fixes automatic coordinates, validates manual coordinates against native coverage, and stores only under `drone/analysis/dayun/fruit-reviews/Agro_ABC/<run>/<block>/`. It reads population corrections to hide rejected plants and follow moved points, without writing their history. Fruit heads remain stable if the detector result changes within the same imagery run; old reviewed fruit points are preserved.

Per-point versions merge independent staff decisions. Same-point conflicts return 409; the viewer preserves an unsaved operation for retry or explicit reload. Successful retries are idempotent. Immutable versions precede the private head write; a failed head write cannot claim success. All API responses and objects are private/no-store. No public catalogue, source TIFF, census, monitoring, planting, ethrel, fertilizer or harvest record is written. New imagery runs have separate fruit histories. This release does not seed production staff confirmations or edit existing team corrections.
