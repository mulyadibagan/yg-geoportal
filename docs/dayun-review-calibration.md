# Private owner-label calibration

This extends the existing radial orientation engine and whole-block counter. No independent app, external model download or census update is involved. Labels, learned parameters, native previews, output candidates and reports belong only in the approved private Dayun analysis prefix; this public repository contains code and synthetic tests only.

`calibrate_dayun_review.calibrate` reads accepted manual points bound to the exact source run and analysis path. It separates a spatial holdout and a buffer from training. Native radial profiles select small-crown scales; training nearest-neighbour distances set suppression, and a broad training-centre brightness guard reduces bare-soil proposals. Brightness or green pixels alone never define a pineapple. A diagnostic copied-template trial is retained for audit but does not select the active radial proposals.

`count_dayun_block.count_block(..., calibration=model)` runs all existing native cores with source halos, checkpoint resume, global seam suppression, source-zone membership and rejection exclusions. It first retains a sensitive proposal pool. `select_dayun_calibrated_result.select_result` chooses the conservative main operating threshold from the **median training-positive peak**, independent of the database totals and holdout outcomes. The sensitive count remains diagnostic and is not the primary map layer. Training/holdout recovery is then measured against the actual global detections, before manual overlap exclusion. No precision, exhaustive recall or whole-block accuracy can be measured from these sparse positives alone.

Model candidates within 12 native pixels of accepted manual labels are excluded from the automatic layer; the labels themselves continue to come from the private team review. This prevents the recognized manual examples from being counted again as automatic points, without injecting missed labels into an automatic detector score. It is a spatial matching rule, not a guarantee against every biological duplicate. Other gawangan, plant ages and species remain unvalidated transfer areas.

Publish a new immutable result folder with the source identity, original asset folder, model signature, source review revision/version, full-block provenance, executed script copies, preview, CSV and unchanged read-only database references. Register the original correction namespace in `manifest.block_review_bases.A` before selecting the calibrated result in `block_analyses.A`. The Worker reads the same private head/history and adapts its analysis path and counts in memory. It never rewrites a user review on read or makes a migration snapshot from a stale local copy. Previously reviewed automatic identities remain valid even if later model versions omit those proposals. New real edits retain per-point concurrency and the existing immutable revision chain.

The viewer displays source-label split, old/new positive recovery, conservative/sensitive counts, manual-overlap exclusions and the private native preview. More candidates or higher recovery at a few known positives does not demonstrate greater count accuracy. Keep the old result files and all user revisions available.
