# Private block comparison and team corrections

Staff open Tools → Analisis Orthomosaic, choose Agro_ABC, and open Blok A. The block link `orthomosaic-internal.html?source=Agro_ABC&block=A` also opens the existing staff-gated viewer. The comparison table sits below the map; its sidebar button leaves the enlarged map and scrolls to the table. Each row can reopen that gawangan in the enlarged map for editing.

The reference table preserves source population, planting month, planted cohorts, recorded initial-plus-cohort total, published living census, seedling stock, and MPTS separately. Fractional source values remain fractional. Unmatched inferred dead-strip IDs remain missing references. Original image candidates and team additions, rejections, acceptances and working count appear separately. A working count includes unreviewed candidates and is not a validated pineapple census. The private comparison file records source timestamps, retrieval time and flight-date provenance; uploads are never treated as flight dates.

Activate edit mode, select a candidate to inspect its native TIFF, accept/reject it or drag its blue handle. To add a plant, choose **Tambah titik nanas** and click the location. The first click loads native imagery and zooms in when needed; a subsequent click on the plant centre creates the point. **Hapus titik tambahan** removes a manually added point. An original automatic candidate can be rejected but cannot be deleted from the baseline. Corrections autosave after two seconds; the revision status confirms successful persistence. Save immediately before leaving, or export a copy if saving fails. Existing sample-review corrections use their own history; this editor edits the whole-block layer.

`GET/POST /api/staff/drone/analysis/Agro_ABC/block-review?block=A` authenticates staff before storage. A dedicated existing DroneQueue Durable Object serializes saves. The server binds corrections to the manifest's imagery run and analysis path, checks IDs, statuses, finite coordinates and native coverage, and derives zone membership from the source polygons. A point inside native imagery but outside all polygons is retained as unassigned boundary-review evidence; no source boundary changes.

Sparse corrections and immutable revisions are stored only under `drone/analysis/dayun/block-reviews/Agro_ABC/<run>/<sha256-analysis-path>/`. Responses and R2 objects use private/no-store. No source points, TIFFs, result index, census data or public catalogue are written by the review API. A changed analysis path starts an independent review history.

Multiple staff laptops can edit simultaneously. The viewer posts `dayun-block-point-patch-v1` operations with point IDs, expected point versions and unique operation IDs. Different points merge against the latest private head, even when a laptop's overall revision is stale. Retrying a successful operation after a lost response does not duplicate it. Manual-point deletions retain version tombstones to prevent an old laptop from silently restoring deleted points. Existing saved revisions are read without rewriting them; their point versions are initialized in memory and carried into the next real save. Old browser tabs may continue using the guarded full-review endpoint, but a stale full save cannot erase newer point edits.

The viewer synchronizes every 15 seconds and overlays unsaved local operations on the team's latest state. Changes made during an in-flight save remain queued with the acknowledged point version. HTTP 409 applies only to points changed on another laptop; those local decisions remain visible, other points can continue saving, and the conflict panel offers **Gunakan titik tim** or **Simpan versi saya untuk titik ini**. The latter deliberately retries against the newly read point version; another concurrent change can still produce a new conflict. Team changes are never silently overwritten. This coordinates point edits, not duplicate biological plants: staff should divide work by gawangan and inspect nearby markers before adding a plant.

Validation covers source/run/coverage rejection, server-side zone assignment, additions and rejection arithmetic, revision conflicts, immutable history, failed head recovery, anonymous denial, native-image placement and private reload. Actual private candidates can be tested locally without sending test decisions to production. Deploy through the existing Drone Survey service workflow; the snapshot publishing workflow must not republish census references during this analysis-only release.
